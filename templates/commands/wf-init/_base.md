# /wf-init — AI Workflow Wizard Bootstrap Wizard

> The wizard is a **state machine with state persisted to disk**.
> Everything discovered or answered lives in `.wizard-state.json` (contract:
> `wf-init/lib/state.md`), NOT in the model's context. The permanent knowledge
> (protocols, rules, templates) lives at
> `https://raw.githubusercontent.com/hugoafj/ai-workflow-wizard/main/templates/` and is downloaded on demand. Artifact assembly is done by a deterministic Builder
> (`wf-init/lib/builder.md`). Consequence: the process is **resumable** even if the
> conversation is lost between two phases.
>
> **When to use**: in the repo where you want to initialize the AI Workflow Wizard.
> This command is **global** — installed once per machine via install.sh and
> works from any repo.
>
> **Related commands** (project-specific, generated by this wizard in Phase 6):
> - `/wf-onboard` — onboarding for developers who clone the repo.
> - `/wf-worktree` — git worktree management.
> - `/wf-settings` — toggle optional modules.
> - `/wf-ladder` — anti-over-engineering (only if wf-ladder active).
> - `/wf-tdd` — TDD protocol (only if TDD + layers active).
> - `/wf-orchestrator` — single entry point (only if routing, ladder, or TDD active).
> - `/wf-sdd-trigger` — SDD decision gate (only if routing active).
> - `/wf-refresh` — updates AGENTS.md when the project evolves (global command).

You are an interactive wizard that initializes the AI Workflow Wizard in this repository.
Execute the phases in order, downloading each phase file from GitHub as you
go. **Each phase ends with a PAUSE and explicit user confirmation before
continuing.** Do not advance without a response.

Your main execution tool is bash. You can read files, list
directories, run commands, and write files.

## Initial setup — Download phase files from GitHub

The wizard downloads the phase files from the wizard's GitHub repo.
This ensures the latest version is always used without needing to
clone the wizard's repo.

```bash
# Wizard's GitHub repo
WIZARD_REPO="hugoafj/ai-workflow-wizard"
WIZARD_BRANCH="main"

# Local directory for downloaded phase files (temporary, can be cleaned up later)
WF_DIR="/tmp/wf-init-phases"
mkdir -p "$WF_DIR"
mkdir -p "$WF_DIR/lib"

echo "Downloading phase files from GitHub..."
echo "Source: ${WIZARD_REPO}@${WIZARD_BRANCH}/wf-init/"

PHASES=(
  "lib/state.md"
  "lib/state-helpers.sh"
  "lib/builder.md"
  "phase0.md"
  "phase0b.md"
  "phase0c.md"
  "phase1.md"
  "phase2.md"
  "phase3.md"
  "phase4.md"
  "phase5.md"
  "phase45.md"
  "phase46.md"
  "phase46b.md"
  "phase47-cicd.md"
  "phase6a-agents.md"
  "phase6b-build-heavy.md"
  "subagent-discovery.md"
  "subagent-builder-core.md"
  "subagent-builder-heavy.md"
  "phase7.md"
  "phase8.md"
)

WF_RAW="https://raw.githubusercontent.com/${WIZARD_REPO}/${WIZARD_BRANCH}"

for phase in "${PHASES[@]}"; do
  curl -fsSL "${WF_RAW}/wf-init/${phase}" > "${WF_DIR}/${phase}" 2>/dev/null
done

if [ ! -s "${WF_DIR}/phase0.md" ]; then
  echo "Error: could not download phase0.md from GitHub."
  exit 1
fi

echo "Phase files downloaded to: ${WF_DIR}"
ls "$WF_DIR"
```

> Phases 6a-6b delegate the Builder to specialized sub-agents to avoid
> exhausting the main agent's tokens. Each sub-agent reads `.wizard-state.json` as the
> single source of truth and writes to `.wizard-staging/`. The state on disk is the
> only storage; wizard templates are downloaded on demand.

## Starting up

First, check if there is an existing run in progress (resumption):

```bash
if [ -f .wizard-state.json ]; then
  PTR=$(jq -r '.phase_pointer' .wizard-state.json 2>/dev/null)
  echo "wf-init run in progress detected. Current phase: $PTR"
  echo "Resume from $PTR, or restart (deletes .wizard-state.json)? [resume / restart]"
  # If resume: cat "$WF_DIR/${PTR}.md"  (or that phase's file)
  # If restart: rm -f .wizard-state.json  and continue below.
fi
```

If there is no run in progress (or the user restarted), read and start Phase 0:

```bash
cat "$WF_DIR/phase0.md"
```

Each phase file includes at the end the exact instruction to read the next one.
Follow those instructions — **do not skip phases or read the next file before
receiving user confirmation**.

## Global rules

- **Mandatory PAUSE** between phases — wait for user confirmation.
- **If the user says "stop"** at any point, stop completely.
- **Do not push** under any circumstances. The user decides when.
- **State lives in `.wizard-state.json`, NOT in your context** (contract:
  `wf-init/lib/state.md`). Each phase READs the state upon entry and WRITEs its section before
  pausing. Do not rely on remembering past decisions: IDEs (Phase 0/5),
  greenfield/legacy classification (Phase 3), SDD backend (Phase 4.5), testing layers
  (Phase 4.6), answers (Phase 5) — everything is read from `.wizard-state.json` in Phases 6-8.
- **Permanent knowledge never travels fully through the context**: when a phase
  needs a rule/protocol, it downloads the corresponding file from
  `https://raw.githubusercontent.com/hugoafj/ai-workflow-wizard/main/templates/` and discards it after use.
