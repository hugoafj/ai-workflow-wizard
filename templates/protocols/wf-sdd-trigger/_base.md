## Activation Contract

Load before implementing any non-trivial change, and before `wf-ladder`/`wf-preflight` are
declared. Decides ONE thing: does this change meet this project's own rules for **explicitly
requesting** gentle-ai's SDD? See `reference/edge-cases.md` for the full rationale and examples.

## Hard Rules

- Never decide or describe HOW gentle-ai routes, delegates, or executes SDD phases — that is
  gentle-ai's native orchestrator's exclusive authority, already installed per adapter. If in
  doubt about delegation mechanics, defer entirely to gentle-ai's own installed content for this
  IDE; never invent or hardcode one here (see `reference/edge-cases.md` for the Windsurf/Devin
  capability-detection nuance).
- Never issue more than one definitive `wf-preflight` per turn; never reclassify mid-response.
- Always ask the user for confirmation of the proposed route — they may choose to override the
  gate's output (e.g., force SDD even if the gate suggested no-SDD, or skip SDD even if the gate
  suggested forcing it).

## Decision Gates

| Condition | Outcome |
|---|---|
| SIMPLE/STRAIGHTFORWARD change: typo, dependency patch, color/spacing, mechanical refactor, simple bug fix (cause & solution clear), or small new feature that is direct (max 3 files, no new abstractions, behavior is obvious from requirements) | `wf-no-sdd` |
| Any change NOT matching the above criteria (default fallback) | `wf-force-sdd` |

## Execution Steps

1. Read enough to know if the change alters existing contracts or introduces new abstractions
   (this exploration does not count as "touching the workspace").
2. Apply the Decision Gates table above, once, to a single definitive outcome.
3. Emit `wf-preflight` (Output Contract) with that outcome.
4. Always ask the user for confirmation: present the proposed route and ask if they want to:
   - Confirm it (if gate said `wf-force-sdd`: proceed to step 5; if gate said `wf-no-sdd`: proceed
     to step 6 below)
   - Override it (if gate said `wf-force-sdd`, ask if they prefer `wf-no-sdd`; if gate said
     `wf-no-sdd`, ask if they prefer `wf-force-sdd`). Loop back to step 3 with the new outcome if
     they choose to override.
5. If confirmed as `wf-force-sdd`: invoke `/sdd-new <feature or fix description>` (foreground, blocking)
   to execute gentle-ai's full SDD pipeline. This satisfies gentle-ai's own
   `explicit_request_or_accepted_proposal` gate. 
   - **Important**: `/sdd-new` is NOT a bash terminal command. It is a natural-language skill invocation that YOU (the agent) execute directly in this conversation, not in a shell.
   - **Fallback without slash**: if your adapter does not support slash commands (e.g., Codex/ChatGPT), invoke literally `sdd-new <feature or fix description>` without the slash — gentle-ai recognizes it as a skill invocation.
   - Never describe the delegation mechanism — gentle-ai's native orchestrator handles that.
6. If confirmed as `wf-no-sdd`: proceed to implement directly (or to `wf-tdd` if that feature is
   active, per the `wf-orchestrator` sequencing).

## Output Contract

`wf-preflight` (once per task, after step 3, awaiting confirmation in step 4):

```
🔍 WF-SDD-TRIGGER
  - Criterion applied: [which condition matched, or "none"]
  - Proposal: [con SDD / sin SDD]
  - Confirm? [sí / cambiar a la otra ruta]
```

After user confirmation (step 4), no additional checklist is required before proceeding.
