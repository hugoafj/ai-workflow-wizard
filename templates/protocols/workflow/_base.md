## Global inviolable rules (all runs)

- **MANDATORY pause between phases**: wait for explicit user confirmation before
  advancing. Do not auto-complete phases.
- **"stop" stops everything**: if the user says "stop" at any time, halt
  completely.
- **Never `git push`**: under no circumstances. The user decides when.
- **Review gate before writing/committing**: show the full diff/artifacts and
  wait for explicit approval.
- **No opportunistic refactor**: apply the new pattern only in new code.
- **Detect binaries with `which`** before assuming they are installed.
- **Heredocs (`cat > file << 'EOF'`)** to write files and avoid variable
  expansion in content.
- **`.gitignore` with `!`**: use `echo '...' >> .gitignore` with single quotes (double
  quotes enable history in zsh).
- **`git shortlog` without range hangs** on repos without commits: always use
  `git shortlog -sne HEAD < /dev/null`.
- **Commit messages compatible with commitlint**: if the project has conventional
  commits (config-conventional), commitlint validates `header-max-length` ≤ 100 and
  `body-max-line-length` ≤ 100. Since the wizard itself configures commitlint and then commits,
  ALL lines of commit messages generated by the wizard (wf-init,
  wf-refresh, wf-settings) must stay ≤ 100 characters, or the wizard's commit fails.
- **Husky v9+**: hooks (`.husky/*`) are direct scripts. Do NOT include the shebang
  `#!/usr/bin/env sh` or `. "$(dirname -- "$0")/_/husky.sh"` — deprecated since v9 (warning)
  and broken in v10. Only the command body.

## State machine

- The state lives in `.wizard-state.json` (see `wf-init/lib/state.md`), not in context.
- Each phase: **reads** state → does its work → **writes** its section and advances
  `phase_pointer` → **pauses**. Resumable even if the conversation is lost.
- Permanent knowledge (this file and the other protocols) is NEVER copied to
  the state; phases download it from `https://raw.githubusercontent.com/hugoafj/ai-workflow-wizard/main/templates/protocols/` and discard it after use.

## Phase routing (canonical order, do not alter)

`phase0 → phase0b → phase1 → phase2 → phase3 → (legacy: phase4) → phase45 → phase46 →
phase46b → phase47 (CI/CD) → phase5 → phase6a → phase6b (Builder) → phase7 → phase8`.

- CI/CD (Block 6) is part of the /wf-init flow: questions in phase47, generation in phase6b.
  It is not optional. Re-configuration happens through `/wf-settings` (options 9–16: CI/CD and release strategy),
  whose single source is the `cicd` protocol (`templates/protocols/cicd/_base.md`).

- The only conditional branch: in `phase3`, if `classification == greenfield` it skips
  `phase4`; if `legacy`, it executes `phase4`. The decision is read from
  `state.discovery.classification`, not from memory.

## Wizard maintenance

- When adding a new command: update the `EXPECTED_COMMANDS` list (phase 2 and
  wf-refresh) and the watched compatibility terms (phase 0). Those lists are the
  source of truth that prevents missing commands in upgrades.
