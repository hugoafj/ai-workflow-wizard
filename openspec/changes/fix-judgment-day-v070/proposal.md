# Proposal: Critical fixes for `v0.7.0-beta.1` (Judgment Day findings)

**Change**: `fix-judgment-day-v070`
**Status**: Proposal
**Created**: 2026-08-13

## Intent

Make the `v0.7.0-beta.1` release usable by fixing the CRITICAL issues found in the `v0.6.6-beta.1..v0.7.0-beta.1` `judgment-day` review:

- `/wf-refresh` cannot run because it tries to `source` Markdown instruction files.
- Version migrations hardcode `0.6.8-beta` and use unsafe string comparison.
- `AGENTS.md` and `AI_DEV_WORKFLOW.md` contradict the builder-driven feature set.
- Custom content preservation and deletion-safety logic are incomplete.

## Scope

### In Scope

1. Rewrite `/wf-refresh` orchestration to download `wf-init/lib/refresher.md` and related files and present them to the agent as **instructions** (same pattern as `/wf-init` phase files), not as bash scripts.
2. Remove `source` calls on Markdown files in `refresher.md`; invoke Builder sub-agents through their existing prompt files (`subagent-builder-core.md`, `subagent-builder-heavy.md`).
3. Replace hardcoded `0.6.8-beta` migration target with a cumulative semver migration that always migrates to the actual `TARGET_VERSION`.
4. Fix `state.md` schema version label and `wizard_version` update logic.
5. Regenerate/sync `AGENTS.md` footer, features table, and commands list to match `builder.md` / `AGENTS.router.md` (`wf-ladder`, `wf-tdd`, `wf-orchestrator`, `wf-sdd-trigger`).
6. Update `AI_DEV_WORKFLOW.md` and `WF_REFRESH_TROUBLESHOOTING.md` to the builder-driven refresh model.
7. Complete custom `AGENTS.md` section preservation in `refresher.md`.
8. Add `deleted_modified` classification for deprecated files edited by the user.
9. Unify `.wizard-managed-files.json` generation and ensure `wf-cleanup` removes it.
10. Bump `VERSION` to `0.7.1-beta.1` (hotfix after `v0.7.0-beta.1`).

### Out of Scope

- New user-facing features beyond the existing `v0.7.0` design.
- Refactoring `/wf-init` unrelated to the `/wf-refresh` fix.
- Adding a real test harness (this project has no test runner); verification stays `bash -n` + manual diff review.

## Capabilities

### New Capabilities

None — this is a corrective release.

### Modified Capabilities

- `wf-refresh`: execution model changes from `source`-based to agent-instruction-based.
- `state-migration`: version migration becomes cumulative and semver-aware.

## Approach

### Option A: Agent-instruction `/wf-refresh` + cumulative semver migrations (chosen)

1. `templates/commands/wf-refresh/_base.md` downloads `wf-init/lib/refresher.md` (and helpers) to a temp directory, then `cat`s / presents it to the agent. The agent executes the bash blocks inside `refresher.md` one at a time, exactly like `/wf-init` phase files.
2. `wf-init/lib/refresher.md` stops `source`ing `migrations.md` and sub-agent Builder prompts. Migration rules move into a pure, comment-safe shell function inside `refresher.md` or into a dedicated `.sh` helper. Builder invocation is done by delegating to the existing sub-agent prompts (`subagent-builder-core.md`, `subagent-builder-heavy.md`).
3. `migrations.md` becomes documentation-only (or is removed) once its logic is absorbed into `refresher.md`.
4. A small semver helper function (`version_lte`) compares versions correctly for the expected `x.y.z[-prerelease]` shape.
5. `AGENTS.md`, `AI_DEV_WORKFLOW.md`, `WF_REFRESH_TROUBLESHOOTING.md` are updated to match the implementation; `AGENTS.md` is generated by the Builder from `AGENTS.router.md` plus feature flags.
6. Preservation/deletion logic in `refresher.md` R3/R4 is completed: re-inject custom AGENTS sections, classify `deleted_modified` files, and write a complete `.wizard-managed-files.json`.

### Why this approach

- It preserves the existing project pattern: Markdown files are **agent instructions**, not shell scripts.
- It fixes the immediate CRITICAL blocker (`/wf-refresh` not executable).
- It makes version migration future-proof for `0.7.x`, `0.8.0`, etc.
- It keeps the change reviewable as discrete work units: refresh execution, migration logic, docs sync, safety logic.
